# iOS CredentialProvider DomainMatcher — PSL Fix

**Status**: approved (LLM Council verdict, 2026-04-23)
**Scope**: iOS credential-provider appex only — Android, TS core, extension, desktop confirmed correct.
**Author**: David Neto (with Claude + LLM Council)

## Problem

`apps/mobile/targets/credential-provider/DomainMatcher.swift` has two bugs that have shipped on every iOS build of KeyKeyKey since the appex was added (PR #10, merged ~2026-03-10):

1. **ccTLD cross-tenant match.** `extractRegistrableDomain` takes the last two hostname segments of a URL. For `bob.co.uk` and `alice.co.uk` both extract `co.uk` — so a credential saved for one UK company surfaces as a match on any other UK company's site. Also fails on `github.io`, `vercel.app`, `herokuapp.com`, `com.br`, `co.jp`, `ac.uk`, and every other multi-segment public suffix.

2. **Substring-as-equality on bundle IDs.** `matchesByAppIdentifier` does `credential.contains { $0.lowercased().contains(lowercasedQuery) }`. Query `"com"` matches every Apple bundle ID. Currently dormant because PR #74 passes `appIdentifier: nil` to the post-unlock picker, but the function is reachable and will re-activate the day anyone wires a caller.

Security reviewer and LLM Council independently flagged both. Council verdict: ship Option F (PSL-aware library replacement for Bug 1, exact-equality for Bug 2) gated on a test fixture that both implementations can be validated against.

Note on Android semantics: Android does bidirectional parent↔child subdomain match (`mail.google.com` matches `google.com` and vice versa) but NOT sibling-subdomain match (`mail.google.com` does NOT match `accounts.google.com`). iOS+TS, after this fix, will treat sibling subdomains as matching because they share a registrable domain. That's a real semantic difference but Android's behavior is strictly safer — we leave it alone. A future ticket can align Android if UX complaints appear.

## Goals / non-goals

**Goals**

- Fix both bugs in the iOS appex.
- Codify matching behavior as a language-neutral JSON fixture that both Swift and TypeScript can validate against.
- Prevent silent drift: CI check that fails if the vendored PSL data is >180 days old.
- Zero functional regression for existing users (sibling-subdomain match is already how TS core behaves — iOS users get MORE matches after the fix, not fewer).

**Non-goals**

- No changes to Android matcher (correct behavior, out of scope).
- No changes to TS core (correct, out of scope).
- No Option E (shared core + JSI bridge). Council explicitly deferred; WebAuthn RP ID is server-declared so passkeys don't need a client-side PSL.
- No data migration of existing vault rows. The appex uses the user's originally-saved URL as-is; we never re-derived a registrable domain at save time, so no stored data carries the bug.
- No new iOS Xcode test target. Adding one to an Expo-prebuild-generated project is significant scope. We use a standalone Swift package runner instead (see Testing below).

## Approach

### Architectural decision: vendor the PSL, write the parser ourselves

Council Executor recommended SwiftDomainParser via SPM. Reality: the iOS Xcode project is generated by Expo prebuild and uses CocoaPods; adding an SPM dep requires either a config plugin or a Podfile patch. Both add brittleness to a prebuild chain that already has five patches applied.

Alternative chosen: vendor Mozilla's `public_suffix_list.dat` (~290 KB text) into `apps/mobile/targets/credential-provider/Resources/public_suffix_list.dat` and write a compact Swift parser (~120 LOC). Advantages:

- Self-contained appex, no Podfile/SPM changes
- Direct control over PSL data → CI staleness check = trivial `stat` on file mtime
- No dependency audit surface (appex runs credential-unwrap code; fewer moving parts is better here)
- Size: ~290 KB text → loaded once into a trie at first call → ~500 KB resident. Appex ceiling is 40 MB. Negligible.

### Swift implementation

**`PublicSuffixList.swift`** (new, ~120 LOC):

- `PublicSuffixList.shared` — singleton loader.
- On first access, mmap `public_suffix_list.dat` from the appex bundle (`Bundle(for:).url(forResource:withExtension:)`).
- Parse: skip blank lines and comments (`//`). Separate ICANN vs PRIVATE sections. Build a reverse-label trie keyed by segments (e.g. `co.uk` stored as `uk -> co -> $terminal`).
- `effectiveTLD(for host: String) -> String?` — walks the trie from the rightmost label, handles `*.ck`-style wildcards and `!example.ck` exceptions.
- `registrableDomain(for host: String) -> String?` — returns `eTLD+1`. If `host == eTLD` (bare suffix), returns `nil`.
- IDN handling: caller must pass an already-ASCII host. We expose a helper `normalizedHost(from: String) -> String?` that prepends `https://` if no scheme, strips userinfo, extracts `.host`, and calls `.idnaEncoded` (via Foundation's `URLComponents` + `String.addingPercentEncoding` fallback).

**`DomainMatcher.swift`** (rewritten):

```swift
import Foundation

/// Normalizes a credential URL or query host to a lowercase, ASCII, punycode-encoded
/// hostname suitable for PSL lookup. Returns nil for IPs, localhost, or unparseable input
/// (caller falls back to exact string match).
func normalizedHost(from input: String) -> String? {
    var s = input.trimmingCharacters(in: .whitespaces)
    if s.isEmpty { return nil }
    // URL(string:) returns nil for bare "example.com/path" — ensure a scheme.
    if !s.contains("://") { s = "https://" + s }
    guard let url = URL(string: s), let host = url.host else { return nil }
    // URL.host strips userinfo already. Punycode normalization:
    let ascii = host.idnaEncoded ?? host.lowercased()
    return ascii.lowercased()
}

/// Returns true iff credential's URL and query resolve to the same registrable domain
/// via the vendored Public Suffix List. Falls back to exact-host equality for IPs,
/// localhost, or hosts where no PSL match applies.
func matchesByDomain(credentialURL: String?, queryDomain: String) -> Bool {
    guard let credentialURL else { return false }
    guard let credHost = normalizedHost(from: credentialURL),
          let queryHost = normalizedHost(from: queryDomain) else { return false }

    // Exact hostname match always wins (covers IPs, localhost, ports).
    if credHost == queryHost { return true }

    // PSL-aware registrable-domain equality.
    let psl = PublicSuffixList.shared
    if let credReg = psl.registrableDomain(for: credHost),
       let queryReg = psl.registrableDomain(for: queryHost),
       credReg == queryReg {
        return true
    }
    return false
}

/// Exact bundle-ID equality. Case-insensitive because bundle IDs are ASCII-only and
/// Apple's convention is lowercase, but some older apps shipped mixed-case.
///
/// App Extensions and App Clips do NOT cross-match their parent app — their bundle
/// IDs are distinct (e.g. com.apple.mobilesafari vs com.apple.mobilesafari.PasswordAutoFill).
/// Users who want their Safari credential to also surface in a Safari extension must
/// save an entry for each bundle ID explicitly. This is the safe trade for a credential
/// manager — parent-app cross-matching would let a rogue app extension request the
/// parent app's credentials.
func matchesByAppIdentifier(credential: [String], query: String) -> Bool {
    let lowerQuery = query.lowercased()
    return credential.contains { $0.lowercased() == lowerQuery }
}
```

### Testing strategy

**TS side**: extend `packages/core/src/domain/domain-utils.test.ts` — load fixture, loop over `domain_cases` + `app_identifier_cases`, assert each. Fails in CI via existing `pnpm test` on `@keykeykey/core`.

**Swift side**: standalone SPM runner at `apps/mobile/targets/credential-provider/__tests__/DomainMatcherRunner/`. Invoked via `swift run DomainMatcherRunner` from CI. Reads the same JSON fixture via a relative path. Includes symlinks or a build-phase copy of `DomainMatcher.swift`, `PublicSuffixList.swift`, and `Resources/public_suffix_list.dat` into the SPM's source tree.

**Manual on-device verification**: after Release build, open Firefox iOS on `davidneto.eu`, `bob.co.uk`-style test domains (use a fresh test credential for each), `github.io` test pages. Confirmed matches align with fixture expectations.

### CI: PSL staleness

**`.github/workflows/psl-staleness.yml`**:

```yaml
name: PSL Staleness
on:
  pull_request:
    paths:
      - 'apps/mobile/targets/credential-provider/Resources/public_suffix_list.dat'
      - '.github/workflows/psl-staleness.yml'
  schedule:
    - cron: '0 9 * * 1' # weekly Monday 09:00 UTC
  workflow_dispatch:
jobs:
  check-psl-age:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Check PSL file age
        run: |
          PSL=apps/mobile/targets/credential-provider/Resources/public_suffix_list.dat
          test -f "$PSL" || { echo "::error::PSL file missing at $PSL"; exit 1; }
          # Use git log rather than file mtime — checkout doesn't preserve mtime.
          LAST_UPDATE=$(git log -1 --format=%ct -- "$PSL")
          NOW=$(date +%s)
          AGE_DAYS=$(( (NOW - LAST_UPDATE) / 86400 ))
          echo "PSL last updated ${AGE_DAYS} day(s) ago"
          if [ "$AGE_DAYS" -gt 180 ]; then
            echo "::error::PSL is ${AGE_DAYS} days old (>180). Run scripts/update-psl.sh and commit the result."
            exit 1
          fi
```

**`scripts/update-psl.sh`**:

```bash
#!/usr/bin/env bash
set -euo pipefail
TARGET=apps/mobile/targets/credential-provider/Resources/public_suffix_list.dat
curl -fsSL https://publicsuffix.org/list/public_suffix_list.dat -o "$TARGET"
echo "Updated $TARGET ($(wc -l < "$TARGET") lines)"
```

Dependabot / Renovate will not track a raw text file, so the user refreshes via the script (roughly quarterly). The CI staleness job enforces cadence.

## Risk & rollback

**Risk**: our handwritten PSL parser has a bug that mis-classifies some exotic suffix. Mitigation: the fixture includes every class of edge the council named; we can add more from real-user reports.

**Rollback**: revert the single PR. No schema migration, no data migration.

**Regression risk for existing users**: before this PR, iOS matcher was unsafe — users on ccTLDs may have been seeing spurious matches (real bug) OR real matches that happened to pass the 2-segment heuristic. After this PR, ccTLD users will see fewer false-positive matches. No user will see fewer legitimate matches (the bug was always over-matching, not under-matching).
